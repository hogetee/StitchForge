# V1 boundaries

This is a runnable Python desktop V1, not a signed/notarized installer. The included local virtual environment runs on this Mac; install the declared dependencies on other machines. Runtime operations require no network.

The current planning baseline and phase-by-phase limits are in [INDUSTRIAL_UPGRADE.md](INDUSTRIAL_UPGRADE.md). Fabric profiles are configurable, uncalibrated test values. Native Wilcom EMB is unsupported; editable files use `.stitchforge`.

- Intended for flat artwork with 1–5 colors. The layer workflow can simplify some shaded illustrations/characters (tested on a textured monkey image), but photorealistic embroidery, complex backgrounds and intricate tiny text remain outside the quality guarantee.
- Images are orientation-corrected and downsampled to at most 1600 pixels on either side. Transparent pixels cannot be selected. Partial alpha is treated as artwork, not composited into a fabric color.
- Direct selection digitizing uses Pillow median cut. Separate into layers uses edge-preserving smoothing and deterministic Lab clustering with a reserved dark-detail seed. The UI defaults to one non-dark material plus optional protected dark details for single-color artwork; **Merge lighting / shadow shades** and **One material silhouette** prevent photographic illumination from becoming extra thread layers. Turn the silhouette option off for genuinely multicolor artwork. These are flat approximations, not semantic material recognition. Layer order/color are editable; global palette reversal applies only to the direct selection workflow.
- Automatic background extraction assumes the object's surroundings provide background samples and uses GrabCut. Subjects touching the crop edge or similar-colored backgrounds can be misclassified. Disable Remove background and draw/refine a manual mask in those cases. Transparent input uses the alpha mask.
- Parts are connected color regions, not guaranteed semantic object names. Eyes/mouth are retained when distinct enough; face/ear boundaries with matching color may need manual splitting. No claim of arbitrary face recognition or automatic semantic naming is made.
- Layer projects have up to 128 parts. Increase minimum part size/smoothing for noisy images. Dark features use a lower pixel/geometry threshold, but details smaller than a needle-scale stitch may still be unsuitable for sewing.
- Contours approximate raster pixel boundaries, with configurable region area filtering and 0.15 mm topology-preserving simplification. Tiny features may disappear. Width and height describe the selected crop; stitch extents may be slightly smaller.
- Running stitches follow polygon boundaries (including holes). The generator accepts arbitrary open polylines, but automatic raster centerline tracing is not implemented.
- Tatami uses clipped alternating rows. Planned mode adds a global stagger phase and bounded routes through unsewn regions; unsafe or expensive routes use jumps. Complicated regions still produce many jumps/trims.
- Planned satin uses a thinned centerline and local-normal rails. Unstable branches, holes, excessive widths and unsafe spans fall back to tatami with a warning. Manual rail editing and professional automatic lettering decomposition are not implemented. Legacy mode uses straight-column inference.
- Planned mode generates contour/center/zigzag/sparse-fill underlay and compensation; legacy mode does not. No automatic tie-in/tie-off, machine-specific tension or calibrated fabric simulation is provided. Barudan trim behavior has not been tested on the user's machine.
- Planned mode applies dependency-constrained sewing order and geometric covered travel/trim decisions. Explicit layer order overrides color savings. Legacy direct-selection mode retains color grouping. Neither algorithm guarantees a global optimum.
- Validation catches missing/invalid/out-of-bounds stitches, maximum-length violations, short stitches, long jumps and dense row settings. It is not a full fabric simulation or hoop collision model. DST quantizes to 0.1 mm; very short segments can collapse after rounding and generate warnings.
- Export verifies needle records and stitch/color-change/end sequence after library normalization. Travel commands may be subdivided by the library. Trim encoding is format-specific and not compared command-for-command. Dimensions in export reports use sewn needle extents, excluding travel.
- DST stores color-change positions, not exact RGB thread colors. Use the UI palette; example verification JSON retains palette information.
- The layer editor provides undo/redo bounded to 20 steps and roughly 96 MB (at least one state); raw selection before creating layers has no undo. Editable `.stitchforge` projects retain embedded source/masks and settings, but stitches/previews are regenerated on reopen. Settings or mask changes invalidate DST export. Unchecked parts are excluded from both simplified artwork and export.
- Progress reports real completed stages/regions and individual fill rows; ETA extrapolates weighted progress and can change. Elapsed time updates between callbacks. Completion is shown only after the result is loaded/rendered. Cancel stops at a safe row/pass boundary; a single contour operation is not interruptible in the middle of its OpenCV call.
- Output sizes are limited to 300 mm per side, row spacing to at least 0.15 mm, and generated designs to 150,000 commands. These limits keep V1 previews responsive; the UI disables editing during background generation.
- Running paths remove redundant collinear nodes and preserve real corners. A corner closer than the requested minimum stitch length may still require a short stitch; the validator warns instead of silently cutting across the shape. Self-intersections are not universally errors because crossing underlay/satin is intentional.
